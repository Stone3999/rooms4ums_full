1. CONTEXTO
--------------------------------------------------------------------------------
La aplicación web tenía un backend propio sobre Supabase (PostgreSQL) y
Upstash (Redis). El objetivo de esta etapa es integrar una aplicación móvil
que reutilice ese mismo backend, de modo que ambas aplicaciones queden
unificadas bajo un único backend y un único sistema de sesión.

Backend unificado: NestJS desplegado en Render
    https://rooms4ums.onrender.com/api
    - PostgreSQL (Supabase) : usuarios, roles, credenciales, salas
    - MongoDB (Mongoose)    : posts y comentarios
    - Redis (ioredis)       : sesiones y canales de voz

3. PENDIENTES

[ ] Canal de voz: requiere cliente socket_io_client contra el gateway existente.

4. NOTAS TÉCNICAS RELEVANTES
--------------------------------------------------------------------------------
- El backend aplica prefijo global /api (setGlobalPrefix en main.ts).
  Toda ruta debe incluirlo: /api/rooms, /api/auth/..., /api/forum/...

- El endpoint de posts por sala responde { data: [...], total: n }, no una
  lista suelta. El cliente desenvuelve ambos formatos por robustez.

- Los posts referencian la sala por SLUG ("general"), no por el UUID de la
  tabla forums. La navegación móvil usa slug.

- Gradle: el proyecto está en disco D: y la caché de Pub en disco C:. Eso
  rompe el caché incremental de Kotlin. Está desactivado en
  android/gradle.properties con kotlin.incremental=false.
